## 1. 实验启动日志

实验在沐曦 MetaX C500 国产 GPU 上启动，采用加固版配置以防 `rq_qos_wait` 死锁：

```
======================================================================
  C500 32场景 × 4模型 × 3seed (加固版, BATCH_SIZE=1)
======================================================================
Device: cuda
GPU: MetaX C500
VRAM: 64.0 GB
mamba_ssm: 2.2.4
Config: D_MODEL=64, BATCH_SIZE=1, MAX_STEPS=100
防护: 每步cuda.synchronize() + 模型间sleep(0.3s) + BATCH_SIZE=1
```

**配置说明：**

| 配置项 | 值 | 说明 |
|--------|-----|------|
| Device | cuda | GPU 加速模式 |
| GPU | MetaX C500 | 沐曦国产 GPU |
| VRAM | 64.0 GB | 显存容量 |
| mamba_ssm | 2.2.4 | Mamba SSM 库版本 |
| D_MODEL | 64 | 模型隐藏维度 |
| BATCH_SIZE | 1 | 批大小（内存安全，防 OOM） |
| MAX_STEPS | 100 | 每组实验训练步数 |

**防护策略：**

- 每步训练后执行 `torch.cuda.synchronize()`：防止 kernel 队列堆积
- 模型间 `sleep(0.3s)`：释放 GPU 资源，防止连续训练死锁
- BATCH_SIZE=1：确保 C500 显存安全

## 3. BP 修复验证日志

实验完成后，系统自动提取所有已完成 BP 模型的调制网络权重范数，验证 v2.1 加法修复是否生效：

```

    bp1_gate=0.4031 bp2_reset=0.4004 bp3_gamma=0.3962

    bp1_gate=0.4339 bp2_reset=0.4164 bp3_gamma=0.4652
  rand_n6_k4|seed456|三链Mamba3+BP
    bp1_gate=0.3713 bp2_reset=0.3706 bp3_gamma=0.3881
```

**字段解读：**

| 字段 | 含义 | 死锁时值 | 修复后值 |
|------|------|----------|----------|
| `bp1_gate` | BP1 空间->时间门控权重范数 | 0.0000（v2 死锁） | 0.37~0.43（非零） |
| `bp2_reset` | BP2 因果->时间 reset 门控权重范数 | 0.0000（v2 死锁） | 0.37~0.42（非零） |
| `bp3_gamma` | BP3 因果->空间 FiLM gamma 权重范数 | 正常（不受乘法影响） | 0.39~0.47（非零） |

**验证结论：**

- **bp1_gate 和 bp2_reset 全部非零**：三个 seed 的权重范数均在 0.37~0.43 范围内，证明 v2.1 加法修复成功打破了乘法梯度死锁
- **v2 对照**：在 v2 乘法实现中，`bp1_gate` 和 `bp2_reset` 恒为 0.0000（两个零初始化网络相乘导致梯度互相阻塞）
- **三 seed 一致性**：不同 seed 下三个调制网络均学到非零值，说明修复稳定可复现
- **BP 完成数 3/96**：截至该日志记录点，96 组 BP 实验（32 场景 × 3 seed）中已完成 3 组（rand_n6_k4 场景的 3 个 seed），断点续跑持续进行中

### 5.2 死锁防护日志要点

实验日志中包含死锁防护相关信息：

- **断点续跑**：脚本启动时检查已有结果数 `NRES`，不删除已完成的实验，从中断处继续
- **自动重试**：单次运行退出后检查是否输出 `C500 EXPERIMENT COMPLETE`，未完成则等待 15 秒后重试（最多 10 次）
- **GPU 重置**：重试前执行 `mx-smi -r` 重置 GPU 状态
- **进程清理**：每次重试前 `pkill -9` 清理残留 Python 进程
